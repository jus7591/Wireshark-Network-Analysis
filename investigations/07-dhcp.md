# DHCP Investigation — DORA Packet Analysis

## Objective

Analyze DHCP traffic generated by a Windows 11 client using Wireshark and understand how a device obtains an IP address through the DHCP DORA process.

The investigation focused on identifying the DHCP packets involved, understanding their purpose, and verifying the resulting network configuration.

## Environment

* Windows 11 client
* Wireshark
* DHCP over IPv4
* UDP ports `67` (server) and `68` (client)
* Windows `ipconfig` commands

## Investigation Process

To generate DHCP traffic, the client released its current DHCP lease and requested a new one:

```powershell
ipconfig /release
ipconfig /renew
```

Wireshark was used to capture and analyze the resulting traffic.

The following display filter was used:

```text
dhcp
```

This isolated DHCP packets from the rest of the captured network traffic.

## DHCP DORA Process

The DHCP exchange followed the standard **DORA** process:

### 1. DHCP Discover

The client broadcasts a **DHCP Discover** message to locate available DHCP servers.

Because the client does not yet have a usable IP address, the initial communication uses broadcast traffic.

### 2. DHCP Offer

The DHCP server responds with a **DHCP Offer** containing proposed network configuration information.

This can include:

* Offered IP address
* Subnet mask
* Default gateway
* DNS servers
* Lease duration
* DHCP server information

### 3. DHCP Request

The client sends a **DHCP Request** indicating that it wants to accept the offered configuration.

This also informs other DHCP servers that their offers were not selected.

### 4. DHCP ACK

The DHCP server responds with a **DHCP ACK** (acknowledgment).

This confirms that the client may use the assigned network configuration.

## Packet Analysis

The DHCP packets were identified in Wireshark as:

```text
DHCP Discover
DHCP Offer
DHCP Request
DHCP ACK
```

The packets used UDP:

```text
Client → Server: UDP 68 → 67
Server → Client: UDP 67 → 68
```

The DHCP transaction contained identifying information such as a transaction ID and client information. These values were intentionally omitted or generalized in this report to prevent exposing unnecessary system-specific information.

The DHCP lease observed during the investigation was approximately **24 hours**, with DHCP renewal timers occurring before the lease expired.

## Configuration Verification

After the DHCP process completed, the resulting network configuration was verified using:

```powershell
ipconfig /all
```

The output confirmed that the client had successfully received DHCP-provided network configuration, including:

* IPv4 address
* Subnet mask
* Default gateway
* DNS server information
* DHCP server information
* Lease information

Sensitive network-specific values such as the actual IP address, gateway address, DNS addresses, and other identifying information have been removed from this documentation.

## Troubleshooting Knowledge

This investigation also demonstrated how DHCP problems can be distinguished from other network problems.

For example, if a Windows client fails to obtain a DHCP address, it may assign itself an **APIPA** address in the `169.254.0.0/16` range.

An APIPA address can indicate that the client was unable to successfully communicate with a DHCP server.

Possible troubleshooting steps include:

1. Verify the physical or wireless connection.
2. Check the network adapter status.
3. Run:

```powershell
ipconfig /all
```

4. Release and renew the DHCP lease:

```powershell
ipconfig /release
ipconfig /renew
```

5. Verify that the client receives a valid IPv4 address.
6. Check whether a default gateway and DNS servers were provided.
7. Use Wireshark to determine whether the DHCP DORA exchange is occurring.
8. Investigate the DHCP server or network infrastructure if the client sends DHCP Discover messages but receives no response.

## What I Learned

* DHCP automatically provides clients with network configuration.
* The DHCP DORA process consists of **Discover, Offer, Request, and ACK**.
* DHCP uses UDP ports **67 and 68**.
* DHCP initially relies on broadcast communication because a client may not yet have a valid IP address.
* Wireshark can be used to observe and troubleshoot the DHCP negotiation process.
* `ipconfig /all` can be used to verify the configuration received from DHCP.
* An APIPA address can be an important indicator of DHCP connectivity problems.
* DHCP troubleshooting should involve examining both the client configuration and the network traffic.
* Packet captures can provide evidence that helps determine whether a problem is occurring on the client, during DHCP communication, or further upstream in the network.
